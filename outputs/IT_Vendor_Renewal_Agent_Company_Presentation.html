1. Business Problem & Executive Value Proposition

Enterprise software renewals represent millions in annual IT operating expenditure. Companies regularly leak 15% to 30% of software spend due to three systematic failures:

  1. Unused Licence Creep (Over-purchasing): Organisations buy seats for forecasted headcounts that are never active. Without automated usage tracking, renewals auto-renew at historical seat counts.
  2. Unenforced SLAs (Service Level Agreements): Vendors breach response time targets repeatedly without accountability or penalty credits.
  3. Passed Notice Deadlines & Auto-Renewal Traps: Contracts with 60 or 90-day written notice requirements roll over into unwanted 12-month lock-ins because legal and procurement miss the notice window.
  4. Hidden Migration Costs: Procurement managers switch to cheaper vendors on paper, only to encounter unanticipated data migration and retraining expenses that erase savings.

Yeh Agent in teeno cheezon ko automate karke company ka paisa bachata hai aur management ko 3 clear options deta hai: Renew, Renegotiate, ya Replace.

4. Detailed Module Architecture & Internal APIs

The codebase is organized into 10 decoupled modules within src/:

1. `contract_reader.py` (Multi-Format Document Reader)

  • Function: read_contract(file_path: Path) -> ContractReadResult
  • How it works: Inspects file extensions (.txt, .pdf, .docx). Uses pdfplumber to extract text page-by-page. If a PDF contains image objects but zero text, it emits an alert: "Document appears to be image-only (scanned). OCR is required."

2. `contract_extractor.py` (Deterministic Regex Term Extractor)

  • Function: extract_contract_terms(text: str, source_file: str) -> ContractTerms
  • Key Feature: Confidence Scoring: Every extracted field has an attached confidence (HIGH, MEDIUM, LOW, NOT_FOUND) and exact quotation snippet.
  • Ambiguous Clause Handling: If a contract has conflicting language (e.g., both automatic renewal and manual sign-off), it flags CONFLICTING — review required with LOW confidence and alerts legal.

3. `retriever.py` (Vendor-Isolated Local RAG Engine)

  • Class: ContractRetriever | Methods: index_document(...), retrieve(query, vendor, top_k)
  • Vendor Isolation Mechanism: All indexed chunks carry a vendor tag. When querying for VendorA, candidate chunks are strictly filtered to VendorA. VendorB chunks are mathematically impossible to retrieve, eliminating cross-contract contamination.

4. `utilisation.py` (Licence Usage & Over-Purchasing Analyzer)

  • Function: calculate_utilisation_rate(df, vendor, threshold=70.0) -> UtilisationResult
  • Spec Test 2: Calculates Average Utilisation = (Active Seats / Purchased Seats) * 100 using Decimal. If average utilisation falls below the configurable 70% threshold (e.g. VendorA at 63.17%), it generates an over-purchasing alert and recommends negotiating seat reductions.

5. `sla_analyzer.py` (SLA Performance & Breach Logger)

  • Function: evaluate_sla_performance(df, vendor) -> SLAResult
  • Spec Test 3: Evaluates every ticket against contractual response targets. Categorizes performance by severity (Critical, High, Medium, Low). Logs exact breach incident IDs (e.g. ['INC-001', 'INC-007']) and generates escalation warnings for critical failures.

6. `cost_comparator.py` (3-Way Financial Matrix Engine)

  • Function: compare_vendor_costs(quotations_df, vendor) -> CostComparisonResult
  • Spec Test 4 (Migration Cost Guardrail): If a replacement vendor quote does not specify migration and onboarding costs, the system marks the replacement option as PENDING and refuses to issue an ungrounded recommendation to replace.
  • Spec Test 5 (Dynamic Quotation Updates): When quotation inputs change, the 1st-year and multi-year savings are dynamically recalculated using Decimal precision.

7. `deadline_monitor.py` (Notice Window & Countdown Engine)

  • Function: calculate_notice_deadline(contract_end, notice_days, reference_date) -> DeadlineResult
  • Alert Hierarchy:
    • PASSED: Deadline has passed. Mandates immediate legal review before any decision.
    • URGENT: ≤ 30 days remaining. Immediate executive escalation required.
    • WARNING: 31 to 60 days remaining. Tender preparation recommended.
    • OK: > 60 days remaining. Normal evaluation timeline.

8. `agent.py` (Safety Orchestrator & State Machine)

  • Class: VendorRenewalAgent | Guardrail: check_forbidden_action(user_input)
  • Spec Test 6 (Action Blocker): Rejects conversational commands like "Terminate contract", "Cancel agreement", or "Sign renewal". Explains that the agent is strictly advisory and only authorized human personnel can execute contracts.

9. `assessment_store.py` (Duplicate-Safe Audit Persistence)

  • Function: save_renewal_assessment(assessment_data, output_dir) -> SaveResult
  • Calculates a deterministic SHA-256 hash of core inputs (vendor, period, costs, dates). Identical re-runs return the existing assessment ID without creating duplicate files, ensuring clean enterprise auditability.

10. `report_generator.py` (Executive Package & Sign-Off Block)

  • Functions: generate_executive_markdown(...), generate_executive_html(...)
  • Produces formal executive decision reports and embeds a 4-tier signature block for IT Vendor Management, Procurement, Legal Counsel, and the CIO.
